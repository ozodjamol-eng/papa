# Оркестр Фабрики

Идея из урока «80% Claude Code» (21.10.2026), доработанная под PAPA: не несколько ручных чатов владельца,
а один главный чат-оркестратор + агенты-исполнители, которых он сам запускает (инструмент Agent).
Владелец ставит задачу и принимает результат — всё между этим делает оркестр.

## Роли
| Роль | Кто | Что делает | Чего НЕ делает |
|---|---|---|---|
| **Оркестратор** | главный чат | бриф, план, ТЗ исполнителям, сборка итогов, журнал, отчёт владельцу | не тратит деньги без «да» владельца |
| **Сценарист** | агент | 3–5 идей + раскадровка по `fabrika-zakaz` (этап 3) | не рендерит |
| **Промптер** | агент | кадры/промпты Kling/Seedance по правилам (этап 4), смета $ | не запускает платные генерации |
| **Монтажёр** | агент | сборка motion/монтажа (`vizavi-motion`, FFmpeg), экспорт | не меняет сценарий без оркестратора |
| **Контролёр** | НОВЫЙ агент, не видел производство | проверка по чек-листу (этап 6), смотрит кадры финального файла | не исправляет сам — только находки |
| **Регламенты** | оркестратор или агент | обновляет журнал заказа и, если приём повторился, скиллы/FISHKI | — |

Простой ролик — оркестр не нужен, хватает `fabrika-zakaz`. Оркестр — когда работ ≥ 2 и их можно делать параллельно.

## Порядок
1. **План.** Оркестратор пишет в журнал заказа (`docs/fabrika/orders/…`): цель, роли, кто от кого ждёт, критерии готовности.
2. **ТЗ каждому исполнителю** — самодостаточное (агент не видит этот чат): клиент, бриф целиком, путь к журналу и
   материалам, нужный скилл (`fabrika-zakaz`, `vizavi-motion`, `ig-caption`…), формат результата, куда положить файлы,
   запреты (платное, публикации, чужие логотипы), язык/письмо.
3. **Параллельно**: независимые задачи запускать одним сообщением (несколько Agent сразу, в фоне).
   Зависимые — по очереди (сценарий → промпты/сборка → контроль).
4. **Контроль**: готовый результат отдаётся новому агенту-контролёру (не тому, кто делал) с брифом и чек-листом.
   Находки → исполнителю на исправление. **Максимум 2 круга**; не сошлось — к владельцу с вопросом и вариантами.
5. **Сдача** — по этапу 7 `fabrika-zakaz` (видео в чат + Telegram), отчёт владельцу коротко: что готово, расход $,
   что требует его решения.
6. **Журнал** обновляется после каждого шага: что сделано, на чём остановились. Любой новый чат продолжит по нему.

## Экономия лимитов
- Исполнителям давать модель по задаче: тексты/промпты/проверка фактов — `sonnet`; простые рутинные — `haiku`;
  сложная режиссура и спорные решения — оркестратор сам.
- Не плодить агентов ради агентов: 2–4 одновременно достаточно.
- Никаких бесконечных циклов и автоповторов платных API (пример из урока: $50 за 1,5 мин в цикле).

## Безопасность
- Платные генерации, публикации в каналы, сообщения клиентам — только после «да» владельца.
- Секреты не передавать агентам и не писать в ТЗ.
- Чужие материалы, которые приносят исполнители (скиллы, скрипты), — через `skill-check`.
