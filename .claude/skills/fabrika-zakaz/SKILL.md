# Фабрика: заказ ролика (стандарт качества PAPA)

Цель: каждый ролик выглядит дорого (не «дешёвка»), правдив и сдан с первого раза.
Большой заказ или несколько роликов сразу — вести через скилл `fabrika-orkestr`.
Журнал заказа — `docs/fabrika/orders/<клиент>-<ГГГГ-ММ-ДД>.md` (шаблон: `docs/fabrika/orders/_SHABLON.md`).
Журнал обновлять на каждом этапе: так любой чат/аккаунт продолжит работу с того же места.

## Этап 1. Бриф (без него не начинаем)
Собрать из сообщения владельца, памяти и журналов; спросить ОДНИМ сообщением только недостающее:
- клиент, товар/услуга, одно главное предложение (оффер), чем лучше других;
- контакты дословно: телефон, адрес, бот/канал (никогда не придумывать и не округлять);
- где выйдет: Хўжаобод Сити 24 (пакет владельца от 21.10: 500 000 сум/нед — ролик + 7 дней показа), Instagram клиента, Telegram клиента;
- формат: 9:16 1080×1920 (Reels/Telegram) по умолчанию; 16:9 — по запросу; длительность 10–20 с;
- язык и письмо: Telegram — узбекская кириллица; Instagram клиента — как его профиль (одно письмо на площадку,
  не смешивать); логотип клиента — как есть (Shodiyona — латиница);
- материалы владельца: фото/видео товара, логотип, цвета; чего нет — отметить.
Правда в рекламе: цифры аудитории, цены, скидки — только реальные. Нет данных — нет цифры.

## Этап 2. Маршрут производства (выбрать дешёвый, который даёт качество)
| Что нужно | Чем | Расход |
|---|---|---|
| Инфографика, текст, логотип, цены, акция, анонс, «здесь ваша реклама» | `vizavi-motion` (HTML/Canvas + FFmpeg) | 0 $ |
| Свои съёмки владельца (цех, интервью, товар) | монтаж FFmpeg + motion-плашки | 0 $ |
| Фото товара → «живое» видео, простые движения | Kling 4.0 (Higgsfield) | цену взять в кабинете (в публичном прайсе нет) |
| То же, дешевле | Kling 3.0 / 2.5 (Higgsfield) | ≈0,084 $/с / ≈0,042 $/с (≈0,42 / 0,21 $ за 5 с) |
| Финальная реклама еды/товара с физикой, «как Apple» | Seedance 2.5 (Higgsfield) | ≈0,206 $/с (со скидкой от 0,144) — 20 с ≈ 3–4 $ |
Генерации — только Higgsfield (не SYNTX и др.). Цены (FISHKI 19.10) сверять с кабинетом перед каждым заказом.
**Сейчас API Higgsfield в PAPA НЕ подключён** (ключа на сервере нет). Пока генерирует владелец в Higgsfield по нашим
готовым промптам (каждый — отдельным блоком для копирования), присылает результат сюда — дальше сборка наша.
Подключение API — отдельный шаг: владелец сам вводит ключ на сервере (секреты не в чат).
**Любая платная генерация — сначала смета в $ и «да» владельца.** Стоимость генераций закладывать в цену клиенту.

## Этап 3. Идея и сценарий
- 3–5 разных идей ролика → выбрать сильнейшую, коротко объяснить почему.
- Хук в первую 1 секунду (что зритель видит первым). Одна мысль на ролик.
- Раскадровка: сцена | секунды | что в кадре | текст на экране | камера | звук.
- Финал 2–3 с: логотип + оффер + контакт крупно, читается без звука.
- Показать владельцу идею+раскадровку ДО сборки, если заказ платный или новый клиент.

## Этап 4. Кадры и промпты для ИИ-видео (если маршрут с генерацией)
- Сначала статичный кадр с композицией; тест «что видно первым за 1 с». Приёмы: ведущие линии к герою,
  рамка (дверь/окно/стекло машины), передний план близко к объективу.
- Промпт Kling I2V: «One continuous 5-second shot, no cuts. The whole time: …» — действие на все 5 с;
  список запретов (no other people, no text, no logo changes, does not walk away…); CFG 0.7; звук генерации ВЫКЛ
  (музыка — в монтаже, генерация со звуком ×1,5 дороже).
- Одно движение камеры на кадр: Push In, Orbit, Crane, Low Angle, Whip Pan, Dolly Zoom (формулировки — FISHKI 18.10).
- Seedance 2.5 — для финала с физикой (еда, жидкость, разрез, ткань): один главный продукт, свет «студия/Apple»,
  чистый фон, 1–2 действия с продуктом; те же запреты; сначала 1 тестовый кадр (≈1–3 $), потом весь ролик.
- Не получилось — не перезапускать тот же промпт: дать конкретную правку.
- Одна нумерация сцен на весь проект. Огонь/пар/жидкость — сверять с референсом до генерации.

## Этап 5. Сборка
- Motion по правилам `vizavi-motion`: камера живая, глубина, типографика в действии, музыка + звуки в ритм.
- Шрифт с узбекской кириллицей: проверить ў қ ғ ҳ на кадре.
- Экспорт: MP4 H.264 yuv420p + AAC, `-movflags +faststart`; motion — 60 fps; монтаж из съёмок/ИИ-видео — частота исходника
  (не поднимать искусственно); размер до 49 МБ (лимит бота), иначе пересжать (`-crf 23`).
- **Водяной знак (владелец 28.10, обязательно в своих роликах OZOD JAMOL):** @Ozodjamol полупрозрачно у края кадра, край меняется каждые ~11 с (кропом не вырезать) — `python3 modules/fabrika/tools/watermark.py вход.mp4 выход.mp4` (до концовки). В клиентских роликах — только если владелец скажет.
- Первая сборка — черновик: пересмотреть кадры по сценам, начало/конец/стыки, исправить, только потом сдавать.

## Этап 6. Контроль качества (чек-лист; при оркестре — проверяет отдельный контролёр)
☐ хук в 1-й секунде ☐ оффер понятен за 3 с ☐ контакты дословно как в брифе, читаются ≥2 с
☐ нет ошибок в узбекском/русском тексте, нет латиницы там, где нужна кириллица ☐ нет чужих логотипов/водяных знаков
☐ нет «пластиковых» лиц, лишних пальцев, кривых букв от ИИ ☐ цифры правдивы ☐ звук не перекрывает голос
☐ формат и длительность по брифу ☐ выглядит дорого (сравнить с лучшими роликами конкурентов)

## Этап 7. Сдача
1. Показать видео прямо в чате (SendUserFile, display=render) — владелец смотрит здесь.
2. Отправить в Telegram (личка от бота PAPA): файлы `outbox/<имя>.mp4` + `outbox/<имя>.txt` (подпись, ≤1024 знака,
   имена одинаковые):
   ```bash
   cd /home/claude/papa && git worktree prune; rm -rf /home/claude/ob
   git fetch -q origin outbox 2>/dev/null && git worktree add -q /home/claude/ob FETCH_HEAD \
     || git worktree add -q --orphan -b outbox-tmp-$$ /home/claude/ob
   cd /home/claude/ob && git rm -rq --ignore-unmatch outbox; mkdir -p outbox
   cp <ролик>.mp4 outbox/<имя>.mp4 && printf '%s' "<подпись>" > outbox/<имя>.txt
   git add -A && git commit -qm "outbox: <клиент>" && git push -q origin HEAD:outbox
   cd /home/claude/papa && git worktree remove --force /home/claude/ob
   ```
   Затем `nexus_papa_task` task=`deliver`; после «отправлено» — очистить ветку пустым коммитом (как `ears` в
   `papa-video-study`), иначе следующий `deliver` пришлёт видео повторно.
3. Коротко: что сделано, расход $ (генерации), что можно улучшить — одной строкой.
4. Журнал заказа: статус «сдан». Исходники (HTML/скрипты, без тяжёлых видео) — в `modules/fabrika/orders/<клиент>/`
   (папку создать при первом заказе клиента).
