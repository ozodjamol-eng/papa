# PAPA — инструкции для ИИ-ассистентов (Claude, ChatGPT, Codex)

Перед любой работой прочитай:
1. `docs/PASSPORT.md` — цель, модули, фазы, правила. Это закон проекта.
2. `docs/STATE.md` — фактическое состояние серверов.
3. `docs/DECISIONS.md` — принятые решения и почему.
4. `docs/CHANNELS.md` — политика каналов: для чего каждый канал и что в нём нельзя.

## Как работать
- Владелец (Ozod, «Papa») говорит по-русски; отвечай по-русски.
- **28.10.2026 владелец: «хватит спрашивать, делай — и впредь».** Бесплатную работу по его задаче — делать сразу, без вопроса «делай?» (коротко сказать, что делаю). Платное (деньги, не кредиты подписок) — по-прежнему смета и «да». Необратимое (удаление, публикация в каналы) — спросить.
- **01.11.2026 владелец: «пора работать самостоятельно — дал указание и ждёшь результат, к этому мы идём».** Задача → ассистент сам выбирает путь (лучший вариант, без меню «А/Б» и без промежуточных вопросов), делает, проверяет и сдаёт готовый результат (чат + Telegram) с коротким отчётом. Отменяет обсуждение сценария/переделки перед работой. Спрашивать только: платное (деньги), публикация, необратимое.
- **Урок 01.11 (владелец: «Я тебе не даю разрешения. Куда ты лезешь?»):** «Отставить» = полная остановка задачи. Неясную реплику после неё («сам сориентируешься») НЕ толковать как разрешение — переспросить. Трата бонусов Flow на видео (Veo) — только после прямого «да» владельца на эту трату, даже если деньги не списываются.
- **Урок 04.11 (владелец: «сколько будешь ошибаться, тратишь мои деньги»):** работа «по образцу» = повторить образец 1:1 (та же модель — если в рефе написано Omni Flash, не подменять Veo; та же камера; тот же тип кадров), меняется только место. Перед КАЖДОЙ тратой бонусов показать владельцу сверку «образец → у нас» по пунктам (модель, первый/последний кадр, движение камеры, цена) и получить «да». Генерировать ОДИН дубль (x1), не два.
- Владелец ставит цели и принимает решения на воротах фаз. Техническую работу (проектирование, код, тесты, проверки) делает ассистент сам.
- Действия, которые может сделать только владелец (вход в его аккаунты, коды, секреты), — собирать в одно сообщение.
- Команды для серверов — готовыми блоками для копирования. Файлы владельцу вложениями не присылать: всё текстом в чате. Исключение — готовые видео: показывать прямо в чате и отправлять в Telegram (ветка `outbox` → `deliver`).
- **ОБЯЗАТЕЛЬНО (25.10.2026):** любая готовая работа (видео, постер, ролик) после показа в чате — СРАЗУ в Telegram владельцу (outbox → `deliver`, оригиналом, без сжатия), без напоминаний.
- В каждом предложении нового — расход в долларах.
- **05.11.2026 владелец: «всегда отправляй после сделанного бот с текстом».** Любой готовый ролик/постер для публикации — кроме файла-оригинала ещё и ГОТОВЫЙ ПОСТ через бот: outbox `<имя>.post.json` (`video`/`photo` + `caption_html`: узбекская кириллица, жирный заголовок, один хэштег рубрики, @канал, призыв переслать) → `deliver`. Владелец пересылает в канал «без имени отправителя». Без напоминаний.
- Секреты никогда не попадают в репозиторий и в чат. Владелец вводит их на сервере сам.
- GENPLAN 5 на Лондоне остановлен 21.10 — не запускать без отдельного решения; боты, базы, старый NEXUS — не трогать без утверждённого шага с откатом.
- **Урок 30.10:** перед любой правкой или предложением по находке аудита — сверить с САМЫМ ПОСЛЕДНИМ решением в `docs/DECISIONS.md` и отличать основной путь от запасного (случай: плашка на старом «Об-ҳаво», который с 27.10 только запасной — основной утренний ролик `dayjest`).
- Публикации в Telegram из кода разработки — запрещены; только тестовый канал.
- Присланное владельцем видео ВСЕГДА изучать полностью: кадры + речь через «Уши» (звук mp3 → ветка `ears` → задача `hear` на Франкфурте → прочитать → очистить ветку). Никогда не делать вывод только по картинке. Порядок — скилл `papa-video-study` (Уши — не больше 6 кусков по 2 мин за заход).
- Чужие скиллы, плагины, скрипты — ставить только после скилла `skill-check` (сканер `scan.py` + ручной просмотр).
- Заказы Фабрики — по скиллу `fabrika-zakaz`; несколько работ сразу — оркестр по скиллу `fabrika-orkestr`. Журнал каждого заказа — `docs/fabrika/orders/`.
- Присланные владельцем ролики/инструменты — учебный материал: сам развивай навыки PAPA (улучшай/создавай скиллы, проверяй рендером) без вопроса, если это бесплатно; платное — только со сметой и «да». Порядок — `papa-video-study` шаг 4а.
- **Фирменная концовка OZOD JAMOL (26.10.2026, навсегда):** в каждый рекламный ролик Фабрики в конец — концовка OZOD JAMOL (`docs/brand/ozod-jamol/koncovka/2s`). Шаблоны роликов — `docs/fabrika/shablony/` (№1 «Живой постер»).
- **Показать, а не описать (30.10.2026, «обратный инжиниринг»):** не понимаю, что владелец хочет (эффект, шрифт, стиль, монтаж) — попросить у него образец, а не угадывать словами. По любому образцу сначала пересказ «✅ точно вижу / ❓ додумываю», владелец правит догадки — потом работа (`motion-po-refu` шаг 1б). Делать маленькими кусками: один приём за раз.
- **Шрифты (31.10.2026, владелец, «впредь»):** в карточках, постерах, превью — только ЖИРНЫЙ, хорошо видимый шрифт (Bold/ExtraBold/Black, напр. Montserrat 800–900), крупно и контрастно. Тонкие и «средние» начертания — запрещены, даже в пробных показах. Тексты для Telegram, которые даём владельцу: заголовок и ключевые строки — жирным. **Урок 31.10:** копия из чата Claude приходит с `**` (Telegram на телефоне их не превращает) — поэтому готовый пост ВСЕГДА присылать через бот (outbox `*.post.json`: `video`/`photo` + `caption_html` с `<b>…</b>` → `deliver`), владелец пересылает «без имени отправителя». В чат — только показ, как будет выглядеть.
- «Сделали руками → сохрани как скилл»: удачная процедура, которая повторится, оформляется скиллом в `.claude/skills/`.

## Структура
- `docs/` — паспорт, состояние, решения, планы фаз.
- `core/` — общее ядро (пространства, площадки, аудитория, источники, материалы, публикации).
- `modules/<имя>/` — razvedka, voronka, genplan, reklama, fabrika, pult.
- `ops/` — развёртывание, systemd, обслуживание серверов.

## Изменения
- Любое изменение цели/модулей/фаз — сначала в `docs/PASSPORT.md` и запись в `docs/DECISIONS.md`.
- После изменений на серверах — обновить `docs/STATE.md`.
- **Урок 31.10 (дизайн):** расстановку розеток, выключателей, света, мебели ассистент решает САМ по своему расчёту (эргономика, высоты, как владелец пользуется комнатой) и пишет в альбоме «почему». Не перекладывать проверку на владельца. Если присланные образцы противоречат друг другу — выбрать самому, объяснить одной строкой.
